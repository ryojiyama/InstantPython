**Ollama 基本コマンド**

| コマンド | 説明 | 実行例 |
| --- | --- | --- |
| `ollama run <モデル名>` | モデルを起動し、チャットを開始します。（未ダウンロードの場合は自動でダウンロードされます） | `ollama run llama3` |
| `ollama list` | Mac内にダウンロードされているモデルの一覧を表示します。（lsでも可） | `ollama list` |
| `ollama pull <モデル名>` | モデルのダウンロードのみを行います。（すぐには起動しない場合） | `ollama pull mistral` |
| `ollama rm <モデル名>` | 不要になったモデルを削除し、ストレージ容量を解放します。 | `ollama rm llama3` |
| `ollama show <モデル名>` | モデルの詳細情報（ライセンス、パラメータ、システムプロンプトなど）を表示します。 | `ollama show llama3` |
| `ollama cp <元> <先>` | モデルを複製します。（プロンプトなどをカスタマイズしたい場合に便利です） | `ollama cp llama3 my-llama` |

## 複数環境での開発ルールとトラブル予防策

自宅と会社など、複数の環境で安全に開発を進め、履歴の消失やシークレット情報の流出を防ぐための基本ルールです。

### 1. 作業前後の同期ルールの徹底
* **作業開始時（編集前）:** コードを1文字でも書き始める前に、必ず `git pull`（VS Codeの「変更の同期」）を実行し、GitHub上の最新状態を手元に反映させる。
* **作業終了時（退社時）:** キリが悪い状態であっても、作業を終える際は必ずコミットして `git push` を行い、リモートを最新状態にしておく。

### 2. シークレット情報（APIキー等）の保護
* APIキーやアクセストークンなどの機密情報は、絶対にコード内（Pythonスクリプト等）へ直接書き込まない。
* 機密情報は `.env` ファイルに記述して環境変数として読み込む。
* リポジトリ作成時は**最優先で `.gitignore` を作成し、`.env` を追記**してGitの追跡対象から外す。

### 3. 強制プッシュ（Force Push）の禁止
* プッシュ時にエラーが出た場合、安易に `git push -f`（強制プッシュ）を使用しない（リモートの履歴が消失する原因になるため）。
* コンフリクト（競合）が発生した場合は、VS Codeのエディタ機能などを活用して視覚的に差分を確認し、手動で正しくマージする。
